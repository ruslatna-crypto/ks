# Настройка и запуск системы приёма заказов в Telegram (INFRAKS)

Документация по архитектуре, локальной разработке и развертыванию серверной функции `/api/order` и формы заказа на странице `/lamp`.

---

## 1. Архитектура и безопасность

### Серверный эндпоинт `/api/order` (`api/order.js`)
- **Серверная обработка**: Заявки отправляются методом `POST` исключительно на серверный эндпоинт `/api/order`. Прямые запросы из браузера в Telegram API не выполняются.
- **Безопасность токена**: Секретный токен бота `TELEGRAM_BOT_TOKEN` и идентификатор чата `TELEGRAM_CHAT_ID` хранятся только в серверных переменных окружения (`process.env`). Переменные **не** имеют префикса `VITE_` и ни при каких условиях не попадают в клиентскую сборку браузера.
- **Универсальность**: Файл `api/order.js` совместим как со стандартными Serverless Functions Vercel (`req.body`, `res.status().json()`), так и с локальным middleware Node.js в `vite.config.js`.
- **Защита от спама и атак**:
  1. **Лимит размера запроса**: Максимум 10 КБ (`413 Payload Too Large`).
  2. **Honeypot-ловушка**: Скрытое поле `company_website` для отлова ботов (`400 Bad Request`).
  3. **Контроль скорости заполнения**: Токен времени открытия формы; формы, отправленные быстрее 1.2 с, отклоняются (`400 Bad Request`).
  4. **Ограничение частоты (Rate Limiting)**: Не более 5 запросов за 10 минут с одного IP-адреса (`429 Too Many Requests`).
  5. **Защита от повторной отправки (Дедупликация)**: Повторный запрос с идентичными данными в течение 30 секунд блокируется.
  6. **Валидация полей**: Строгая проверка обязательных полей (имя от 2 символов, телефон от 6 цифр, валидация формата email).
  7. **Подтверждение доставки**: Клиенту возвращается статус `ok: true` **только после** подтверждения 200 OK и `ok: true` от Telegram Bot API (`sendMessage`). Если переменные окружения отсутствуют или Telegram вернул ошибку, сервер возвращает статус ошибки (500 или 502) с понятным описанием, не имитируя успешную отправку.

## 3. Локальный запуск и разработка

В проекте настроена автоматическая загрузка серверных переменных в `vite.config.js` через `loadEnv`, а также встроен серверный middleware для обработки запросов `/api/order`.

### Шаг 1. Запуск сервера разработки
```bash
npm run dev
```
Сервер запустится по адресу: `http://localhost:5173/`

### Шаг 2. Открытие страницы заказа
Перейдите на страницу:
```
http://localhost:5173/lamp
```
Форма заказа расположена внизу страницы, непосредственно перед подвалом (`Footer`).

### Шаг 3. Автоматизированное тестирование бэкенда
Для проверки эндпоинта `/api/order`, валидации и доставки в Telegram без браузера запустите:
```bash
node scripts/test_order_api.js
```
Скрипт проверяет:
- Отклонение неверного HTTP-метода (405);
- Отлов спам-ботов через honeypot (400);
- Валидацию недостающих данных (400);
- Ошибку при отсутствии токена (500);
- Реальную отправку тестовой заявки в Telegram (200 OK).

2. Откройте **Settings** → **Environment Variables**.
3. Добавьте переменные для сред **Production**, **Preview** и **Development**:
   - `TELEGRAM_BOT_TOKEN` = `8298692023:AAH7Eyq-ZgMXjdyqWFA1YgFC_9czyorh4Jc`
   - `TELEGRAM_CHAT_ID` = `193632181`
4. Нажмите **Save**.

### 2. Маршрутизация в `vercel.json`
В файле `vercel.json` уже настроено исключение `/api/` из SPA-перенаправления:
```json
{
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "rewrites": [
    {
      "source": "/((?!api/|admin/|uploads/|assets/|images/|robots\\.txt|sitemap\\.xml|favicon\\.ico|favicon\\.svg|config\\.yml).*)",
      "destination": "/index.html"
    }
  ]
}
```
Файл `api/order.js` автоматически распознаётся Vercel как бессерверная функция (Serverless Function) по маршруту `https://<ваш-домен>/api/order`.
